# Unity Quest VR AI Performance Optimization Guide

## Overview

This document describes the performance optimizations implemented to prevent frame drops and the spinning hourglass indicator when using AI features (microphone, STT, LLM, TTS) on Meta Quest VR devices connected via Link cable.

## Problem Analysis

### Root Causes of Frame Drops

The Meta Quest shows the loading hourglass when:
1. **Frame time exceeds threshold**: >13.9ms at 72Hz, >11.1ms at 90Hz
2. **Main thread blocking**: Any operation that takes >5-10ms on main thread
3. **GC spikes**: Large garbage collection pauses (50-200ms)

### Identified Blocking Operations in Original Code

| Operation | Location | Typical Duration | Impact |
|-----------|----------|------------------|--------|
| `File.ReadAllBytes()` | GPTConnector, OpenAISpeechRecognizer | 5-50ms | High |
| `File.WriteAllBytes()` | TextToSpeechPlayer, OpenAISpeechRecognizer | 5-50ms | High |
| `Convert.ToBase64String()` | GPTConnector (audio encoding) | 10-100ms | Critical |
| `Convert.FromBase64String()` | GPTConnector (audio decoding) | 10-100ms | Critical |
| WAV header parsing | GPTConnector | 5-20ms | Medium |
| JSON parsing | GPTConnector | 2-10ms | Medium |
| `AudioClip.Create()` + `SetData()` | TextToSpeechPlayer | 5-30ms | High |
| `new byte[large]` allocations | Various | GC pressure | High |
| `new List<float>` allocations | OpenAISpeechRecognizer | GC pressure | High |

## New Components

### 1. ThreadPoolDispatcher (`Performance/ThreadPoolDispatcher.cs`)

Singleton that safely dispatches work between Unity main thread and background threads.

**Key Features:**
- Lock-free queue for main thread callbacks
- Limited actions per frame to prevent spikes
- Built-in helpers for common operations

**Usage:**
```csharp
// Run expensive work on background thread, callback on main thread
ThreadPoolDispatcher.Instance.RunAsync(
    () => Convert.ToBase64String(largeData),  // Background work
    result => ProcessResult(result)            // Main thread callback
);

// Async file I/O
ThreadPoolDispatcher.Instance.ReadFileBytesAsync(path, bytes => {
    // Process bytes on main thread
});
```

### 2. Object Pools (`Performance/ObjectPools.cs`)

Pre-allocated, reusable object pools to minimize GC pressure.

**Available Pools:**
- `ByteArrayPool`: Size-bucketed byte arrays (1KB-1MB)
- `FloatArrayPool`: Audio sample buffers
- `StringBuilderPool`: JSON construction
- `FloatListPool`: Audio capture lists
- `MemoryStreamPool`: WAV encoding streams

**Usage:**
```csharp
// Rent a buffer
byte[] buffer = ByteArrayPool.Instance.Rent(4096);

// Use buffer...

// Return when done
ByteArrayPool.Instance.Return(buffer);
```

### 3. StreamingAudioPlayer (`Performance/StreamingAudioPlayer.cs`)

Non-blocking audio playback using ring buffers.

**Key Features:**
- Background thread processes PCM chunks
- No AudioClip creation blocking
- Handles Quest Link latency
- Low-latency streaming start

**Usage:**
```csharp
// Begin streaming
streamingPlayer.BeginStream(24000, 1);

// Add chunks as they arrive (can be called from any thread)
streamingPlayer.AddPcmChunk(pcmBytes);

// Mark complete when done
streamingPlayer.MarkStreamComplete();
```

### 4. AsyncAudioProcessor (`Performance/AsyncAudioProcessor.cs`)

Static helpers for common audio operations on background threads.

**Available Methods:**
- `BuildWavFromPcm16Async()`: PCM16 → WAV
- `ExtractPcm16FromWavAsync()`: WAV → PCM16
- `EncodeBase64Async()`: Bytes → Base64
- `DecodeBase64Async()`: Base64 → Bytes
- `ReadWavFileAsPcm16Async()`: File → PCM16
- `ProcessAudioResponseAsync()`: Full pipeline

### 5. WavUtilityPooled (`Performance/WavUtilityPooled.cs`)

Thread-safe WAV utilities that don't require Unity main thread.

**Methods:**
- `FromFloatArray()`: Float samples → WAV bytes
- `FromPcm16()`: PCM16 → WAV bytes
- `ExtractPcm16()`: WAV → PCM16
- `Pcm16ToFloat()`: PCM16 → Float samples
- `Resample()`: Sample rate conversion

### 6. QuestPerformanceSettings (`Performance/QuestPerformanceSettings.cs`)

Runtime performance monitoring and optimization.

**Features:**
- Frame timing monitoring
- Incremental GC scheduling
- Quality settings optimization
- Foveated rendering control
- Emergency GC on consecutive slow frames

## Setup Instructions

### 1. Add QuestPerformanceSettings to Scene

1. Create an empty GameObject named "PerformanceManager"
2. Add `QuestPerformanceSettings` component
3. Configure settings:
   - Target Frame Rate: 72 (Quest 2) or 90/120 (Quest 3)
   - Enable Aggressive GC Management
   - GC Interval: 0.5s

### 2. Add StreamingAudioPlayer (Optional)

For streaming TTS playback:
1. Add `StreamingAudioPlayer` component to your TTS player
2. In GPTConnector Inspector:
   - Enable "Use Streaming Audio"
   - Assign the StreamingAudioPlayer reference

### 3. Verify ThreadPoolDispatcher Exists

The `ThreadPoolDispatcher` auto-creates itself when first accessed. No manual setup needed.

## Best Practices

### 1. Never Block Main Thread

```csharp
// ❌ BAD - Blocks main thread
byte[] data = File.ReadAllBytes(path);

// ✅ GOOD - Background thread
ThreadPoolDispatcher.Instance.ReadFileBytesAsync(path, data => {
    // Process data
});
```

### 2. Use Pooled Allocations

```csharp
// ❌ BAD - Creates garbage
var list = new List<float>(16000);
var buffer = new byte[65536];

// ✅ GOOD - Reuses memory
var list = FloatListPool.Instance.Get(16000);
var buffer = ByteArrayPool.Instance.Rent(65536);

// Don't forget to return!
FloatListPool.Instance.Return(list);
ByteArrayPool.Instance.Return(buffer);
```

### 3. Spread Work Across Frames

```csharp
// ❌ BAD - Process all at once
foreach (var item in items) Process(item);

// ✅ GOOD - Yield between items
IEnumerator ProcessOverTime() {
    foreach (var item in items) {
        Process(item);
        yield return null; // Give time to render
    }
}
```

### 4. Pre-warm During Loading

```csharp
void Start() {
    // Pre-warm pools during scene load
    for (int i = 0; i < 4; i++) {
        var buffer = ByteArrayPool.Instance.Rent(65536);
        ByteArrayPool.Instance.Return(buffer);
    }
}
```

## Quest-Specific Settings

### Unity Project Settings

1. **Player Settings > XR Settings**
   - Stereo Rendering Mode: Single Pass Instanced
   - Low Overhead Mode: Enabled

2. **Player Settings > Other Settings**
   - Scripting Backend: IL2CPP
   - Api Compatibility Level: .NET Standard 2.1
   - Managed Stripping Level: Medium

3. **Quality Settings**
   - Pixel Light Count: 1
   - Texture Quality: Full or Half
   - Shadow Distance: 0 (disable shadows)
   - Soft Particles: Off
   - Anti-Aliasing: 4x MSAA or Off

4. **Audio Settings**
   - DSP Buffer Size: Good Latency (512) or Best Latency (256)

### OVRManager Settings (if using Meta XR SDK)

```csharp
OVRManager.fixedFoveatedRenderingLevel = OVRManager.FixedFoveatedRenderingLevel.High;
OVRManager.useDynamicFixedFoveatedRendering = true;
```

## Monitoring & Debugging

### Enable Performance Logging

In `QuestPerformanceSettings`:
- Enable "Log Frame Timing Warnings"
- Set threshold to 11ms for 90Hz

### Watch for These Warnings

```
[QuestPerf] ⚠️ Slow frame: 15.2ms (target: 11.1ms)
[QuestPerf] 🚨 3 consecutive slow frames, triggering emergency measures
```

### Unity Profiler

Use the Unity Profiler via USB to identify remaining hotspots:
1. Build with Development Build enabled
2. Connect via USB
3. Open Profiler in Unity Editor
4. Look for spikes in:
   - Scripts (main thread blocking)
   - GC.Alloc (memory allocations)
   - Rendering (too many draw calls)

## Troubleshooting

### Hourglass Still Appears

1. Check if all async patterns are correctly applied
2. Look for remaining synchronous file I/O
3. Check for large JSON parsing on main thread
4. Verify GC is running incrementally

### Audio Underruns

1. Increase `startThresholdSeconds` in StreamingAudioPlayer
2. Increase DSP buffer size in Audio Settings
3. Reduce audio sample rate if possible

### Memory Growing

1. Ensure all pooled objects are returned
2. Check for leaked coroutines
3. Verify MemoryStreams are disposed
